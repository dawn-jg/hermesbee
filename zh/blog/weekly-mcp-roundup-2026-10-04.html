MCP 生态周报：Agent Skills 成为协议扩展、无状态规范正式落地、OpenAI 开放 ChatGPT 插件 SDK（2026年10月4日）

作者 HermesBee Team · 开发者工具 · 2026年10月4日 · 6 分钟阅读

本周的 MCP 由两件协议级事件和一次厂商开放定义。其一，Agent Skills 扩展（SEP-2640）合并为 Final，把 skill:// 资源与 skills/list / skills/get 接口正式写进标准；其二，2026-09-28 无状态架构由 Agentic AI Foundation 正式定稿——这正是 7 月版规范预告的那一步；其三，OpenAI 发布了官方 ChatGPT MCP 插件 SDK。与此同时，供给端仍在复利：公共服务器超过 19831 个，SDK 月下载约 9700 万次。

Agent Skills 变成协议扩展

SEP-2640（"Skills Extension"）于 2026-09-13 合并为 Final，是 2026-07-28 版本之后第一个落地的 SEP。它规定了 MCP 服务器如何把 Agent Skills 作为一等资源暴露：

  • 用 skill:// URI 约定寻址单个技能；
  • 两个必需方法 skills/list 与 skills/get，负责发现与读取；
  • 可选的 resources/directory/read，支持目录式访问；
  • 扩展标识符 io.modelcontextprotocol.skills。

在此之前，"skill"一直是各家 harness 的私有功能：同一个文件夹，一个客户端会加载，另一个视而不见。SEP-2640 把它变成一个可移植格式，带着标准的发现与读取接口——MCP Inspector 甚至提前四天在 2.6.0 里支持了它。对维护本地技能库的人来说，结论很直接：你已经在用的那份结构，从此可以被任何合规服务器寻址；而市场里缺的那一环，已经从"格式"变成了"分发"。

无状态规范正式落地

2026-09-28，Linux 基金会下的定向基金 Agentic AI Foundation 发布了 MCP 史上最大的一次更新。无状态架构就此定稿：没有握手、没有 Mcp-Session-Id、没有黏性路由。OAuth 签发者（iss）校验成为强制项，协议特性开始适用正式的 12 个月弃用政策，MCP Apps 与 MCP Tasks 从扩展草案转正为官方扩展。官方 Go SDK v1.8.0 同时加固了资源耗尽防护——JSON 嵌套深度、SSE 事件大小、stdio 帧长、OAuth DCR 响应全部设限。

含义：凡是按旧会话假设写的 MCP 产品，传输层都要按"modern（2026-07-28+）"模型重写。好处也很具体——无状态服务器可以直接跑在 Cloudflare Worker 上，既压低托管成本，也去掉了让第三方 MCP 托管一直别扭的黏性会话路由问题。

OpenAI 开放 ChatGPT 插件 SDK

openai/mcp-extensions（Apache-2.0）是让 MCP 服务器在 ChatGPT 里"像原生功能一样"的官方做法：

  • 侧边栏入口——你的工具拥有自己的面板；
  • 针对特定文件类型的自定义查看器；
  • 输入框里的 @ 提及；
  • 富表单（图片选择、表单收集），让 Agent 能要求结构化输入。

npm 包 @openai/mcp-extensions 已发布 v0.1.0（PyPI 侧也有），仓库本周越过约 719★ 且在持续推送。但它很早期——0.1.0 的 API 一定会变，插件的审核门槛也尚未公开。务实的做法是先把现有某一个服务器包成一个 demo 壳，再谈复用；它真正的价值是：在既有的 MCP 目录之外，多出一条分发入口。

变现仍然是难点

一个有用的事实核对：MCP 协议本身没有计费层（官方文档明说），所以每个付费服务器都在协议外自己接一层，于是四种模型并行、没有一家主导。

模型例子形态
按次AgenticMarket每次 $0.03–$0.50
平台托管订阅MCPize平台抽成
按事件Apify PPE$0.05/地点 · $0.002/评论 · $0.01/AI 提取
执行配额MCPBundles每月 25 次免费

2026 年的一线记录给出的现实天花板是每月 $500–$10,000+，公开的成功案例大多落在 $500–$3,000。三份诚实复盘里反复出现同三条规则：免费额度不要按"调用次数"给（要和真实成本挂钩，因为 Agent 几秒就能烧掉人类一个月的量）；把"购买决策"（人，按月）和"消耗决策"（Agent，按额度）分开；以及把最贵的那个工具单独定价，否则 Agent 会专门盯着它刷。

安全与治理

MCP 安全工作组发布了 threat model v1.0——工具输出里的提示注入、供应链风险、权限提升——现已被规范作为非规范附录引用。RFC-0041 提议为工具调用标准化一个错误响应信封（code / message / retryable）。客户端侧，Claude Desktop 0.9.4 把"逐服务器工具确认"做成了标准功能：每次确认、仅写操作确认、或从不确认。若你漏看了上周的 MCP 服务器安全指南，简短版结论没变——锁版本、收窄文件系统授权、永远不要相信工具描述。

仍空着的几个供给位

  • 技能分发层——SEP-2640 给了接口，但"技能界的 npm"还没人做。
  • 应用商店运营 MCP——magaza-mcp 覆盖 App Store Connect 与 Google Play，却只有约 87★ 且仅土耳其语。
  • 本地优先的 Agent 可观测性——agent-console（约 795★）逐会话记录 token、缓存与成本，但它是写给作者自己的，不是写给买家的。
  • AI 文档 lint——seiso（约 173★，Rust，crates.io / npm / PyPI 三发）证明了"检查 AI 写的 Markdown 是否符合约定"这个需求是真实的。

我们如何评估 MCP 服务器

标准没变，而且本周又把它钉实了一次：能不能搞定最难的 30%——反爬墙与动态页（见 Cloudflare 绕过指南）？是否本地运行、一次性买断，而不是每次调用计费？返回结构化数据还是原始 HTML——原始 HTML 是每次调用都要付的"上下文税"（见 MCP 抓取服务器指南）？以及在碰你的数据之前，能不能过一遍安全审查？上一期见 9 月 27 日 MCP 周报。

HermesBee 的判断

本周三条头条里有两条和我们的路线同向。无状态利好轻量的自托管服务器，而不是托管中间件；Skills 扩展则让本地技能库变得可移植，而不是被客户端锁死。所以我们继续把 Unified Scraper MCP、CF Bypass Browser MCP、LLM Scraper MCP 及全部产品做成本地、买断、可审计的工具——无账号、无云依赖、无按次计费。当规范自己开始标准化"发现"与"交付"时，我们当初选的架构就不再是一种偏好，而开始成为默认形态。

总结

本周 MCP：Agent Skills 经 SEP-2640 成为协议扩展（skill:// 与 skills/list）；无状态架构于 2026-09-28 定稿，配套 12 个月弃用政策，MCP Apps / Tasks 转为官方扩展；OpenAI 以 v0.1.0 发布 ChatGPT 插件 SDK；变现问题仍未解——没有计费层，四种模型并行。我们每周发布一篇这样的周报。
